# `mkdyifs` (work in progres)

`mkdyifs` is a tool that generates `ifs.build` for the `mkifs` tool. It's name stands for "make dynamic image file system (IFS)".

## File structure
`mkdyifs` is a bash script that read and manipulate files in QNX SDP installation directories and scripts files in this directoies.
- `presets`
A "preset" is a configuration file written in bash syntax that describes the content of `ifs.build`.
- `hooks`
A "hook" is a startup task (OpenRC in the future, sheel scripts for now) that runs in the order describe in "presets"
- `install`
Every file in the `install` directory describe a set of files in the IFS, see `mkifs`'s documentation for the syntax
- `common`
Shared files between different presets, usually no need to be modified for new presets

## Boot 
IFS generated by `mkdyifs` should follow the timeline below when booted:
```
Power ON <-----Usually hardware failues-------\
|                                             |
V                                             |
Boot into the IFS                             |
|                                             |
V                                             |
Initialize PCI and character device drivers --/
|
(stage 0, basic shell) X-----Boot stopped-----\
|                                             |
V                                             |
Mount filesystem -----Can not mount FS--------/
|
(stage 1, LATE INIT, IFS done)
|
V
Initialize other drivers (i.e. io-sock)
|
V
Done
```

- Stage 0, a basic shell should be available for debugging. This will only provided limited system utils and IFS only files for debugging and emergency rescue
- Stage 1, the whole filesystem shoud now be available. The system should now trying to initialize other system drivers or services like `io-sock`, graphics/screen using binaries from the disk rather than the IFS.

After stage 0, the IFS should do nothing other than the kernel itself and PCI drivers.
